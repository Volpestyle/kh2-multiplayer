# Passive combat causal diagnostic

Offline product prerequisite for the two-PC shared-combat design, based on clean source 7d622b414694167c70794931bb58e253db18344f. These are new coherent DLL/runtime products, not the original JOIN27 binaries. Full combat remains BLOCKED until the source/product reviews, measured transport coverage and a separate executable fixture qualify. No game run or recording-window decision is included.

Set `KH2COOP_COMBAT_CAUSAL_TRACE=1` explicitly on both the inject process and its runtime. Absent or any other value is off. The flag reuses the installed ApplyHitDamage/TakeDamage/StatHP observation hooks and owner-thread trace; it adds no hook registrations, network packets, damage calls, retries or gameplay permissions. Existing NativeHitTrace::Witness is unchanged.

Admission requires two consecutive owner frames with five living object-302/type-4 Shadows in full native tuple `[5,6,0,1,1,0]`, fresh checked actor/object/status/controller/record roots, a two-peer roster and complete native/session/lifecycle gates. Original generation, delivery, peer deliveries, session salt, connection IDs, epoch, load, transition and target mappings remain immutable. The salt supplements the exact runtime session receipt; it is not authentication by itself. Same-pointer native incarnation remains unqualified. Any replaced scope, unexplained HP change, missing living target, extra family/wave, loss or ambiguity permanently retires diagnostic coverage. It never changes gameplay behavior.

The fixed owner-thread ledger links canonical host native hit events or actual friend claim application to the normal EnemyHp publication. It copies the existing encoded payload at the existing enqueue, source sequence and ordered per-target cause IDs. Friend hit claims retain the enclosing ApplyHitDamage event sequence and immutable actual claim key. Client HP/death decode, actual native store/lethal call and checked readback have distinct receipts. Grace/despawn cannot qualify a natural death. Native fault/partial outcome cannot qualify.

`[combat-causal] receipt` and association lines retain numeric kind/reason, QPC nanoseconds, complete original scope, target roots, native before/after values, actual operation outcomes, claim keys, raw payload and cause IDs. The payload FNV64 is a convenience checksum only: reviewers must compare raw bytes, framing and independently hash retained artifacts. `[hittrace]` remains the detailed original hit/child/policy evidence. `[combat-causal-runtime]` binds exact session bytes (hex), transport/producer generation and delivery to actual net submission or inbox admission. Inbox admission is not native application. All records have `acceptance=0`; no local boolean can substitute for cross-peer replay and the full combat oracle.

The observer uses a static 128-row receipt queue, five targets and 16 causes per target, with 4096 payload bytes per row. Hook-side work uses copied facts, fixed storage and no I/O or allocation. Owner-frame drain emits at most 16 receipts; loss is explicit and invalidates completeness. Runtime receipts are bounded to 4096 relevant packets; overflow emits a loss marker. Its logging and any envelope decoding are outside native hooks. Runtime/DLL QPC clocks are local only, never compared between PCs.

Offline controls exercise production NativeHitTrace callbacks and the actual EnemySync claim consumer and normal HP publisher over owned synthetic memory. They check unchanged original calls/arguments/returns/sends with the flag off/on, cause association, replacement, unsupported source, unknown damage, duplicate application, death classification, raw payload retention, client readback and fixed-ring loss. Copied facts and benign native leaves are not live native coverage. Build and serial CTest results, compiled-input provenance and product hashes belong to the sealed product packet.
